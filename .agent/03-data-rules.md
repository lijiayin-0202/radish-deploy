## 1. 基础数据口径

| 编号 | 口径 |
| --- | --- |
| D-01 | 金额单位为人民币分，整数，**不使用浮点数**；不含运费和优惠 |
| D-02 | 一单仅购买一种商品，数量只能是 1 或 2 件 |
| D-03 | 活动商品单价 10000 分，初始可售 5 件；预置 2 个商品、3 个买家及运营/仓库/客服账号 |
| D-04 | 应付金额 = 下单时单价 × 数量；订单保存下单时的商品与价格，后续上下架与调价不改已有订单金额 |
| D-05 | 待付款订单保留 10 分钟，超时判断采用服务端时间；演示缩短时长须注明，测试与线上演示规则一致 |
| D-06 | 只能购买在售且数量足够的商品；创建订单后可售数量须反映已占用数量 |
| D-07 | 核心业务数据入库，服务重启后订单、库存、收退款、异常与审计结果仍可查询 |

## 2. 库存数据口径

| 编号 | 规则 |
| --- | --- |
| K-01 | 可售数量 = 初始可售数量 − 未释放占用 + 已登记释放 / 恢复 |
| K-02 | 下单预扣该订单数量（1 或 2 件）；预扣与订单创建在同一事务内，禁止「有订单无占用」 |
| K-03 | 主动取消或超时关闭释放占用一次；**重复关闭不多释放** |
| K-04 | 正常售前退款经渠道确认成功后恢复相应可售数量一次 |
| K-05 | **迟到支付对应的退款不得再次恢复此前已释放的数量**；已发货订单不恢复库存 |
| K-06 | 库存变化逐笔留痕，原因分为预扣、取消释放、关闭释放、正常售前退款恢复；同一订单同一原因至多一笔 |
| K-07 | 20 个并发下单请求争抢 5 件时不得超卖：已占用 + 可售 = 5 |

## 3. 订单状态机（数据视角）

| 状态 | 含义 | 终态 |
| --- | --- | --- |
| 待支付 | 已创建、库存已预扣、等待有效期内有效支付通知 | 否 |
| 待发货 | 有效期内收到并校验通过的支付通知，已记款一次 | 否 |
| 退款审核中 | 已申请整单售前退款，发货暂停 | 否 |
| 退款处理中 | 客服同意，等待渠道结果；失败时停留由客服重试 | 否 |
| 已取消 | 买家主动取消，占用已释放一次 | **是** |
| 已关闭 | 服务端时间满 10 分钟超时关闭，占用已释放一次 | **是** |
| 已退款 | 渠道确认整单退款成功，正常售前退款已恢复可售数量 | **是** |
| 已发货 | 仓库登记承运方与运单号一次 | **是** |

**允许流转**：创建 → 待支付；待支付 → 待发货（有效通知）/ 已取消 / 已关闭；待发货 → 退款审核中 / 已发货；退款审核中 → 待发货（拒绝）/ 退款处理中（同意）；退款处理中 → 已退款（渠道成功）/ 退款处理中（渠道失败重试）。

**禁止流转**：已关闭或已取消 → 待发货（迟到支付不恢复订单）；已发货 → 退款相关状态；已退款 → 已发货；退款审核中或退款处理中 → 已发货；待发货及之后 → 已取消或已关闭；任意终态 → 任意其他状态；待支付 → 已发货。

> **迟到支付不改变订单状态**，只生成异常支付待处理记录；校验不通过的支付通知同样不产生跳转，仅留存处理结果。

## 4. 原题 8 条业务规则（数据落地逐条）

| 规则 | 数据约束 | 可核查的数据结果 |
| --- | --- | --- |
| 规则 1 | 只能购买在售且数量足够商品；订单保存下单时商品与价格；可售数量反映占用 | 订单金额快照不变；预扣记录与订单一一对应 |
| 规则 2 | 待付款 10 分钟；主动取消或超时关闭释放占用；重复关闭不多释放；服务端时间 | 释放记录每单每因至多一笔；可售数量不重复增加 |
| 规则 3 | 通知须鉴权、匹配订单及金额；重复通知不重复记款；同一渠道交易号不得归属两单；金额不符、未知订单、验签失败可查询 | 收款记录 1 条；三类校验失败各有可查询处理结果；交易号唯一 |
| 规则 4 | 有效期内校验通过的通知使订单进入待发货；关闭后成功通知不能恢复订单或重新占用库存，进异常支付待处理列表由客服核实后发起退款 | 订单保持已关闭终态；异常支付记录 1 条；库存未重新占用 |
| 规则 5 | 已付款未发货可申请整单退款；申请期间暂停发货；客服同意/拒绝并写明原因；拒绝后允许继续发货；退款与发货同时发生只形成一种合法结果 | 审核记录含审核人与原因；不存在「已退款且已发货」 |
| 规则 6 | 渠道确认成功后买家可见结果；正常售前退款恢复相应可售数量；渠道明确失败保留待处理由客服重试；迟到支付退款不得再次恢复已释放数量 | 退款金额 = 实收金额；恢复记录一次；失败待处理记录可查；迟到支付退款显示「不恢复」 |
| 规则 7 | 仓库只为合法待发货订单登记一次发货；已发货订单不受理本题售前退款；不实现签收、退货及售后物流 | 发货登记 1 条，运单号不重复 |
| 规则 8 | 运营按订单查询收款、退款、发货、异常处理记录，查看可售数量、已收款及已退款汇总；异常记录不能通过直接修改订单状态消失 | 汇总与逐笔记录一致；异常记录始终可查；订单状态只读 |

## 5. 5 个强制演示场景的数据断言

| 场景 | 关键数据断言 | 禁止出现的结果 |
| --- | --- | --- |
| 活动正常成交 | 2 件订单应付 20000 分；已收款 20000 分、已退款 0 分、可售 3 件、发货 1 条、异常 0 条；状态已发货 | 金额用小数；收款与发货记录缺失 |
| 缺货与弃单 | 20 并发争抢 5 件，成功预扣合计 ≤ 5；已占用 + 可售 = 5；被拒请求有原因；释放后其他买家可再次购买 | 超卖；重复释放；孤立占用 |
| 售前退款 | 申请期间发货被拒；首次渠道失败保留待处理；重试成功；恢复数量 = 订单数量且仅一次；退款金额 = 实收金额 | 部分退款；重复退款；重复恢复库存 |
| 迟到支付 | 订单保持已关闭终态；异常支付记录 1 条、退款 1 条；客服处理原因留痕；无重复释放、无重复退款 | 订单复活；库存二次恢复；异常记录消失 |
| 操作竞争 | 并发只形成一种合法业务结果；重复通知不重复记款/退款；同一交易号不归属两单；越权明确拒绝并留痕 | 双重业务结果；重复记款；他人数据泄露 |

## 6. 数据一致性红线

- 审计流水记录所有状态变更，**只追加、不可修改、不可删除**。
- 异常支付、验签失败、金额不符、未知订单、退款失败记录独立留存，不随订单状态改写而删除。
- 所有失败或拒绝操作必须产生可展示的原因（原型文档 M-01~M-30）。
- 金额、库存、状态、收退款记录在同一事务内一致提交；禁止写死成功结果。

## 7. 权限数据隔离

| 角色 | 可见数据域 |
| --- | --- |
| 买家 | 仅本人订单、本人退款结果、本人运单 |
| 仓库 | 合法待发货订单及本人发货登记结果 |
| 客服 | 退款申请、异常支付待处理列表、支付通知处理结果、渠道退款结果 |
| 运营 | 全部订单、商品、收退款与发货记录、异常记录、审计流水（只读核查） |
| 模拟支付渠道 | 仅支付/退款受理与回调，不查询商城业务数据 |
