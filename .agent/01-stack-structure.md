# 01 技术栈与工程结构

| 项 | 内容 |
| --- | --- |
| 适用项目 | `shop-trade`（题目 01：小型电商的订单交易、发货与售前退款） |
| 文档定位 | `.agent/01-stack-structure.md`：技术选型、架构边界、目录结构与模块划分 |
| 架构 | GVA（gin-vue-admin）**单体架构**，单 Go 服务 + 单 MySQL（InnoDB）实例 + 可控 HTTP 模拟支付渠道 |
| 后端 | Go + Gin + Gorm |
| 数据库 | MySQL（InnoDB）；核心业务数据必须入库，服务重启后结果仍可查询 |
| 原型 | 极简 HTML 页面，4 类角色 8 个视图（V-01~V-08），不做 CSS 美化 |
| 第三方 | 全部为可控 HTTP 模拟服务，仅模拟支付渠道；不得表现为真实第三方 |
| 明确禁用 | **Kratos、Kafka、pgvector**；同时不引入微服务拆分、消息队列、分布式锁、真实第三方支付、真实物流 |
| 上游文档 | 需求文档 v1.0、原型设计文档 v1.0、任务规划文档 v1.1、根目录 `AGENTS.md`、`commit-convention.md` |
| 业务范围 | 仅题目 01 电商订单交易闭环，不含任何其他题目或业务域 |

## 1. 架构边界

| 编号 | 约束 |
| --- | --- |
| A-01 | 单体单进程：商品、订单、库存、支付通知、退款、发货、异常支付、核查、审计均在同一 Go 服务内完成，不做服务拆分 |
| A-02 | 单库：所有业务表在同一 MySQL（InnoDB）库中，状态变更与库存变化在同一事务内提交 |
| A-03 | 并发安全**优先使用 MySQL InnoDB 事务 + 行锁**（锁定订单行 / 商品可售数量行），不依赖 Kafka、缓存或分布式锁；更新条件必须命中索引，否则会升级为表锁，引发超卖风险；详见 `02-layering-codegen.md` |
| A-04 | 模拟支付渠道为独立可控 HTTP 服务，只能以通知形式触发商城状态变化，不得直接改写商城数据 |
| A-05 | 不引入与本题无关的组件；组件数量不作为评分依据 |
| A-06 | 前端仅提供可操作的极简 HTML 页面，页面刷新查询即可，不做 SPA、WebSocket、长连接 |
| A-07 | 所有业务表建表必须指定 `ENGINE=InnoDB`、字符集 `utf8mb4` |

## 2. 目录结构（GVA 约定）

| 路径 | 用途 | 本题是否可修改 |
| --- | --- | --- |
| `.agent/` | 本约束集 6 个 md 文件 | 可新增；修改须经学生确认 |
| `server/core/` | 框架启动入口 | **禁止修改** |
| `server/global/` | 全局配置、DB 句柄 | **禁止修改** |
| `server/initialize/` | 框架初始化 | **禁止修改**（仅通过配置项接入） |
| `server/middleware/` | 框架中间件 | **禁止修改** |
| `server/config/` | 配置结构定义 | **禁止修改** |
| `server/utils/` | 框架工具 | **禁止修改** |
| `server/api/v1/` | 请求绑定、参数校验、响应封装 | 仅新增本题接口文件，不写业务逻辑 |
| `server/router/` | 路由注册 | 仅新增本题路由注册 |
| `server/model/` | 数据模型及 `request/`、`response/` | 仅新增本题业务结构 |
| `server/service/` | **本题全部业务逻辑** | 可写（唯一业务落点） |
| `server/migrate/` | 初始化与演示数据 | 可新增本题初始化数据 |
| 原型页面目录 | 极简 HTML 角色页面 | 可写 |
| 模拟支付渠道目录 | HTTP 模拟服务与通知记录 | 可写 |
| 根目录 | `AGENTS.md`、`commit-convention.md`、三份上游文档、CI 配置 | 按约束维护 |

## 3. 本题业务模块划分（全部落在 `server/service/`）

| 模块 | 职责 | 关联需求文档 |
| --- | --- | --- |
| 商品与下单 | 在售与可售校验、下单快照、金额计算、库存预扣 | R-01~R-05 |
| 订单状态 | 8 状态机、10 分钟超时关闭、主动取消、重复关闭不多释放 | 第 4 章、R-06~R-08 |
| 支付通知 | 鉴权、订单匹配、金额匹配、渠道交易号唯一、幂等记款 | R-14~R-19 |
| 异常支付 | 迟到支付登记、客服核实、原因记录、退款发起 | R-20~R-24 |
| 售前退款 | 整单申请、审核同意/拒绝、渠道成功/失败重试、库存恢复 | R-25~R-30 |
| 发货 | 合法待发货校验、承运方与运单号登记一次 | R-31、R-32 |
| 权限与核查 | 角色身份、越权拒绝、运营按订单查询与汇总 | R-33~R-39 |
| 审计流水 | 所有状态变更只追加记录 | R-40、N-17~N-21 |

> 上表为逻辑模块划分，不是微服务拆分；禁止据此创建独立服务或引入消息中间件。

## 4. 数据与技术口径

| 项 | 口径 |
| --- | --- |
| 金额 | 整数「分」，不使用浮点数 |
| 商品 | 预置 2 个；活动商品单价 10000 分、初始可售 5 件、在售 |
| 订单 | 一单仅一种商品，数量 1 或 2 件；应付金额 = 下单时单价 × 数量 |
| 时间 | 服务端时间；待支付保留 10 分钟；演示可配置教学时钟但须注明 |
| 状态 | 8 个订单状态、4 个终态，以需求文档第 4 章为准 |
| 审计 | 审计流水只追加、不可修改、不可删除 |
