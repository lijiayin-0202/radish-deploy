# 06 开发流程与三 Agent 协作

| 项 | 内容 |
| --- | --- |
| 适用项目 | `shop-trade`（题目 01 电商订单交易） |
| 文档定位 | `.agent/06-workflow-devflow.md`：三 Agent 会话隔离、职责、交接材料、开发流程与里程碑 |
| 强制约束 | 开发 Agent、测试 Agent、验收 Agent **会话强制隔离、职责严格分开** |
| 业务范围 | 仅题目 01 电商订单交易，不混入任何其他业务域 |

## 1. 三 Agent 会话隔离（强制）

| 编号 | 规则 |
| --- | --- |
| S-01 | 三个 Agent 可使用同一工具与同一模型，但**必须使用相互独立的会话或任务上下文**，会话记录分别导出 |
| S-02 | 测试 Agent 与验收 Agent 必须读取原始题面与对应版本代码，不得仅根据开发 Agent 的完成声明判断通过 |
| S-03 | 三个角色不得互相代写对方交付物、不得进入对方会话修改其文件；AI 自述「通过」不作为验收依据 |
| S-04 | 学生是唯一可跨会话协调、确认边界变更、发起合并与确认验收结论的人 |
| S-05 | 每次会话须记录：阶段、任务编号、模型、关联代码版本、输入与输出位置 |

## 2. 职责严格分开

| 维度 | 开发 Agent | 测试 Agent | 验收 Agent |
| --- | --- | --- | --- |
| 阶段 | Agent 开发 | Agent 测试 | Agent 验收 |
| 任务编号 | DB-01/02、MOCK-01/02、BE-01~04、UI-01~05、DOC-02 | TST-01~08、TST-S1~S5 | ACC-01~05 |
| 核心职责 | 在 `dev/01` 实现题目 01 业务闭环与 8 个原型视图 | 执行三轮验证中的第 1、2 轮并出具证据 | 执行第 3 轮浏览器页面验收并逐项核对题面 |
| 输入 | 原始题面、三份上游文档、AGENTS.md、约束集、经核验的需求编号 | 原始题面、需求/原型/任务文档、对应版本代码、运行说明、缺陷清单 | 原始题面、三份上游文档、对应版本代码、三轮全部证据、Skill 与 AI 记录 |
| 输出 | 源码、初始化文件与演示数据、模拟支付渠道、8 个 HTML 页面、运行说明、开发会话 | 测试计划、单元测试、覆盖率与 race 原始输出、Apipost 用例与结果、缺陷与复测记录、测试报告 | 逐项结论与证据位置、验收报告、门禁核验清单、Skill 检查闭环记录 |
| 生产代码 | **可写** | 只读 | 只读 |
| 测试文件 | 只读 | **可写** | 只读 |
| 验收报告 | 只读 | 只读 | **可新增** |
| 判断依据 | 需求与验收条件 | 实际执行结果 | 原始题面 + 对应版本代码 + 证据 |

## 3. 可修改范围与边界

| 编号 | 规则 |
| --- | --- |
| M-01 | 开发 Agent 只在 `dev/01` 修改 `server/service/` 业务代码、本题 `api`/`router`/`model` 新增文件、`migrate` 初始化数据、原型页面、模拟支付渠道、运行说明 |
| M-02 | **GVA 底层框架代码禁止修改**（`core`、`global`、`initialize`、`middleware`、`config`、`utils`），见 `02-layering-codegen.md` |
| M-03 | 测试 Agent 只修改测试相关文件、缺陷记录与测试报告；不得修改生产代码，发现缺陷交回开发 Agent 修复后复测 |
| M-04 | 验收 Agent 对业务与测试代码只读，仅可新增验收报告类文档（`docs` 类型且经学生确认） |
| M-05 | **禁止擅自扩大需求边界**：不得新增购物车、售后退货、一单多商品、真实第三方支付、真实物流、部分退款、多商户、促销优惠、签收与售后物流、完整财务系统 |
| M-06 | 题面未明确事项查需求文档第 8 章假设清单；仍未覆盖的记录新假设并经学生确认，**禁止脑补额外需求** |

## 4. 交接材料

| 阶段 | 交付方 | 接收方 | 交接材料 | 证据位置 |
| --- | --- | --- | --- | --- |
| 需求 / 原型 / 任务规划 | 学生 | 三个 Agent | 原始题面、需求文档 v1.0、原型文档 v1.0、任务规划 v1.1、AGENTS.md、`.agent/` 约束集、commit-convention.md | `dev/01` 的 `docs` 提交与会话导出 |
| 开发完成 | 开发 Agent | 测试 Agent | 源码、初始化与演示数据、模拟支付渠道、8 个页面、运行说明、提交哈希 | `dev/01` 的 `feat` 提交 |
| 缺陷登记 | 测试 Agent | 开发 Agent | 缺陷清单、修正要求、复现步骤 | 缺陷登记记录 |
| 缺陷修复 | 开发 Agent | 测试 Agent | `fix` 提交说明与编号核验输出 | 提交哈希与核验记录 |
| 测试完成 | 测试 Agent | 验收 Agent | 覆盖率原始文件、race 输出、Apipost 结果、缺陷及复测记录、测试报告 | 测试会话与报告索引 |
| 验收完成 | 验收 Agent | 学生 | 逐项结论、证据位置、验收报告、门禁核验清单 | 验收会话 |
| PR / 合并 | 学生 | 部署 | PR 记录、状态检查结果、版本对应关系 | 仓库记录 |

## 5. 开发流程（题面七阶段 + 8 小时）

严格执行：需求分析 → 原型设计 → 任务规划 → Agent 开发 → Agent 测试 → Agent 验收 → 自动部署上线。

| 阶段 | 分钟 | 主要任务 | 完成条件 |
| --- | --- | --- | --- |
| MCP 建仓与 Agent 约束准备 | 20 | 建仓、`dev/01`、编写并加载 AGENTS.md 与 `.agent/` 约束集 | 分支就绪、约束开发前生效 |
| 需求分析 | 35 | 需求文档 v1.0（前序已完成） | 角色、规则、状态、假设、验收条件齐全 |
| 原型设计 | 20 | 原型文档 v1.0（前序已完成） | 8 个视图、显隐矩阵、异常文案齐全 |
| 任务规划 | 20 | 任务规划 v1.1（前序已完成） | 任务编号、依赖、完成判定、需求对应关系齐全 |
| 开发 | 180 | DB、MOCK、BE、UI、Skill 编写 | 业务闭环可操作、结果持久化、三层分层合规 |
| 测试 | 75 | 单元测试 + race、Apipost、缺陷与复测 | 覆盖率 ≥85%、无数据竞争、接口用例通过 |
| 验收 | 40 | 浏览器页面验收、逐项核对 AC-01~AC-25 | 独立会话逐项通过、5 组场景完整演示 |
| Git 合并与自动部署 | 35 | PR 门禁、合并、主分支重新执行门禁、部署与冒烟 | 门禁全通过、地址与版本可核查 |
| Skill 总结与视频提交 | 55 | `skill-usage.md`、AI 过程记录、班级群提交与视频 | 证据齐全、视频覆盖 5 组场景 |
| **合计** | **480** | — | 测试或验收发现问题时修复后重新验证受影响阶段 |

## 6. 里程碑与门禁

| 里程碑 | 进入条件 | 门禁结论 |
| --- | --- | --- |
| M0 准备 | 仓库、`dev/01`、AGENTS.md 与约束集就绪 | 约束开发前生效，分支合规 |
| M1 开发 | DB、MOCK、BE、UI 任务完成 | 业务闭环可操作、service 层合规、结果持久化 |
| M2 测试 | 三轮验证第 1、2 轮通过 | 覆盖率 ≥85%、race 无报告、Apipost 全通过 |
| M3 验收 | 三轮验证第 3 轮通过 | 独立验收会话逐项通过、Skill 闭环证据齐全 |
| M4 合并 | PR 门禁全部通过 | 仅通过 PR 合并且状态检查通过，未直接推送 `main` |
| M5 上线 | 主分支重新执行门禁、部署与冒烟通过 | 地址、版本、冒烟结果可核查 |
| M6 提交 | 交付清单、AI 过程记录、视频齐全 | 当天群提交完成，证据可追溯 |

## 7. AGENTS.md 与 Skill

| 编号 | 规则 |
| --- | --- |
| K-01 | 项目级 `AGENTS.md` 须在业务开发开始前自行编写并实际使用，保留历史版本与加载记录，不得完工后补写 |
| K-02 | 至少两个自编 Skill：业务专项 Skill（检查订单、库存、支付、退款、发货之间的约束与跨环节异常）、验收检查 Skill（核对 5 组场景、测试证据与部署结果） |
| K-03 | 每个 Skill 含用途、触发场景、输入、执行步骤、输出格式、失败处理、完成标准；须提交配置文件与实际调用记录 |
| K-04 | 至少一次「Skill 检查发现问题 → 学生指导 Agent 修正 → 重新检查」闭环；未发现问题须保留检查范围与依据，不得编造缺陷 |
| K-05 | 提交 `skill-usage.md`，未实际调用的不得列为已使用 |

## 8. 禁止行为

| 编号 | 禁止 |
| --- | --- |
| P-01 | 三个 Agent 共用会话、互相代写交付物、职责混同 |
| P-02 | 编造接口、依赖用法、执行结果、测试报告、覆盖率数据或部署成功记录 |
| P-03 | 删除失败测试 case、弱化断言、跳过关键路径、任意排除生产代码凑覆盖率 |
| P-04 | 密钥、访问令牌、演示口令、签名密钥进入仓库、日志、截图、对话导出或视频；相关内容一律脱敏 |
| P-05 | 直接提交或推送 `main`、伪造 meegle 核验、混合类型提交 |
| P-06 | 修改 GVA 底层框架代码、在 `api` 层写业务逻辑、引入 Kratos / Kafka / pgvector / 分布式锁 |
| P-07 | 擅自改动题面 8 条规则、状态机、验收条件或假设并当作既定需求 |
| P-08 | 验收后修改业务代码不重新验证；拿开发分支旧报告当作主分支证据 |
