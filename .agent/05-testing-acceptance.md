# 05 测试与验收（三轮强制验证）

| 项 | 内容 |
| --- | --- |
| 适用项目 | `shop-trade`（题目 01 电商订单交易） |
| 文档定位 | `.agent/05-testing-acceptance.md`：三轮验证、覆盖率、Apipost、浏览器页面验收 |
| 强制轮次 | 第 1 轮单元测试 + `go test -race`；第 2 轮 Apipost 接口自动化；第 3 轮浏览器页面验收 |
| 覆盖率门槛 | 自编 Go 生产代码整体语句覆盖率 ≥85%，**核心业务包分别 ≥85%** |
| 业务范围 | 仅题目 01 电商订单交易，5 个强制演示场景三轮全部覆盖 |

## 1. 三轮验证总表

| 轮次 | 验证方式 | 执行 Agent | 输入 | 交付产出 | 通过标准 |
| --- | --- | --- | --- | --- | --- |
| 第 1 轮 | 单元测试 + `go test -race` 竞态检测 | 测试 Agent（独立会话） | 原始题面、需求文档、对应版本代码 | 测试原始输出、覆盖率原始文件、race 报告、可读报告 | 全部通过；整体与核心业务包覆盖率各 ≥85%；无数据竞争报告 |
| 第 2 轮 | Apipost 接口自动化 | 测试 Agent（独立会话） | 第 1 轮通过版本、接口清单、预置数据 | Apipost 用例与断言清单、运行导出结果 | 全部接口用例通过；5 组场景端到端链路断言全部满足 |
| 第 3 轮 | 浏览器页面验收 | 验收 Agent（独立会话） | 前两轮证据、8 个原型视图、对应版本代码 | 页面验收记录、逐项结论、脱敏截图、时间点目录 | 4 类角色 8 个视图可操作；5 组场景完整演示；失败原因可见 |

> 三轮顺序不可颠倒、不可跳过；任一轮失败须登记缺陷 → 在 `dev/01` 修复 → 从失败轮次起重新验证受影响范围 → 验收 Agent 复核。

## 2. 第 1 轮：单元测试与竞态检测

| 编号 | 要求 |
| --- | --- |
| U-01 | 覆盖正常流程、边界条件、非法状态、重复操作、权限校验及本题指定异常路径（E-01~E-16） |
| U-02 | 核心业务包（订单状态、库存、支付通知、退款、发货、异常支付、审计）分别 ≥85%；集成测试不得代替单元测试 |
| U-03 | 自编数据库访问、HTTP 处理代码不得自行排除；自动生成文件与第三方代码可排除，其他排除项须事先明确并在报告列出 |
| U-04 | 20 并发下单、退款与发货并发、重复支付/退款回调等共享并发逻辑须有**可重复执行**的并发验证，并执行 `go test -race`，无数据竞争报告 |
| U-05 | 同时执行 `gofmt`、`go vet`；质量检查失败不得继续发布 |
| U-06 | 提交单元测试命令、原始输出、覆盖率原始文件与可读报告 |
| U-07 | **禁止**删除失败测试 case、弱化断言、跳过关键路径、任意排除生产代码凑覆盖率；禁止编造测试结果或覆盖率数据 |

## 3. 第 2 轮：Apipost 接口自动化

### 3.1 环境与分组

| 项 | 内容 |
| --- | --- |
| 环境 | 本地 / 教学验收环境 base URL；预置 3 个买家、运营、仓库、客服账号；活动商品 10000 分、可售 5 件 |
| 接口分组 | 商品与下单、订单查询与取消、支付通知、退款申请与审核、发货登记、异常支付处理、运营核查 |
| 模拟触发 | 通过模拟支付渠道 HTTP 服务触发正常回调、重复回调、迟到回调、退款成功、退款失败、验签失败、金额不符、未知订单 |
| 变量 | 订单编号、渠道交易号、运单号、金额（分）、当前订单状态、可售数量 |

### 3.2 断言口径

| 编号 | 断言 |
| --- | --- |
| P-01 | 状态码与业务结果一致；金额字段恒为整数分 |
| P-02 | 订单状态符合状态机，终态不可回退 |
| P-03 | 库存守恒：已占用 + 可售 = 5；重复关闭不多释放 |
| P-04 | 幂等：同一订单连续 3 次相同成功通知只记款一次；同一交易号不归属两单 |
| P-05 | 校验失败：金额不符、未知订单、验签失败均有可查询处理结果，订单状态不变 |
| P-06 | 迟到支付：订单保持已关闭终态，异常支付记录可查，不重新占用库存 |
| P-07 | 退款与发货互斥：并发只形成一种合法业务结果；失败待处理可重试 |
| P-08 | 权限：越权查看或处理他人订单明确拒绝，不返回他人数据 |
| P-09 | 异常记录与审计流水只追加、可查询、不可消失 |

### 3.3 五组场景端到端用例

| 场景 | Apipost 链路 | 关键断言 |
| --- | --- | --- |
| 活动正常成交 | 上架 → 下单 2 件 → 支付成功 → 发货登记 → 订单查询 → 运营核查 | 20000 分；已发货；已收款 20000、已退款 0、可售 3 |
| 缺货与弃单 | 20 并发下单 → 部分取消/超时关闭 → 其他买家再下单 | 无超卖；释放后可再次购买；重复关闭不多释放 |
| 售前退款 | 付款 → 申请退款 → 发货被拒 → 客服同意 → 渠道失败 → 重试成功 | 恢复数量 = 订单数量；退款金额 = 实收；仅一次 |
| 迟到支付 | 订单关闭 → 迟到成功通知 → 异常列表 → 客服核实 → 发起退款 → 运营核查 | 订单仍已关闭；无重复释放、无重复退款；库存不二次恢复 |
| 操作竞争 | 退款申请与发货并发、重复支付/退款通知、越权请求 | 唯一合法结果；不重复记款/退款；越权被拒 |

**交付证据**：Apipost 用例清单（含断言）、运行导出结果、失败用例与复测记录、对应提交版本。

## 4. 第 3 轮：浏览器页面验收

### 4.1 页面范围

| 角色 | 视图 | 验收要点 |
| --- | --- | --- |
| 买家 | V-01 商品浏览页、V-02 我的订单列表&详情页 | 仅本人订单；下单、付款、取消、整单退款申请按钮按状态显隐 |
| 运营 | V-03 商品管理页、V-04 运营对账核查汇总页 | 上下架与售价/可售数量维护；汇总与逐笔一致；订单状态只读 |
| 仓库 | V-05 待发货订单列表、V-06 发货录入表单 | 仅合法待发货可登记；退款中显示「暂停发货」；重复登记被拒 |
| 客服 | V-07 退款审核列表、V-08 迟到支付异常处理列表 | 同意/拒绝与核实须写原因；迟到支付订单恒显已关闭终态；异常记录常显 |

### 4.2 验收判定

| 编号 | 判定 |
| --- | --- |
| W-01 | 与原型文档 3.1 按钮显隐矩阵一致：8 个订单状态下显示/隐藏/只读正确 |
| W-02 | 每个失败操作展示 M-01~M-30 中文原因，无空结果、无写死成功 |
| W-03 | 所有展示字段来自数据库持久化结果，服务重启后仍可查询 |
| W-04 | 5 组强制演示场景在浏览器中从业务起点演示到结束核查，不能只演示成功主路径 |
| W-05 | 越权查看或处理他人订单被明确拒绝并留痕 |
| W-06 | 结果来自对应提交版本；截图、日志脱敏，不含密钥与令牌 |

**交付证据**：页面验收记录、逐项结论与证据位置、脱敏截图、带时间点的讲解目录。

## 5. 三 Agent 在三轮中的职责边界

| Agent | 第 1 轮 | 第 2 轮 | 第 3 轮 |
| --- | --- | --- | --- |
| 开发 Agent | 提供代码版本与运行说明，不参与判定 | 提供接口说明，不参与判定 | 不参与判定；仅按缺陷清单在 `dev/01` 修复 |
| 测试 Agent | **执行并出具证据** | **执行并出具证据** | 提供前两轮证据，不参与验收判定 |
| 验收 Agent | 只读核对证据真实性 | 只读核对证据真实性 | **执行并出具逐项结论** |

> 三个 Agent 会话强制隔离；验收 Agent 必须读取原始题面与对应版本代码，不得仅凭开发或测试 Agent 的完成声明判断通过。

## 6. 验收条件与缺陷闭环

| 编号 | 要求 |
| --- | --- |
| V-01 | 逐项核对需求文档 AC-01~AC-25，每项给出「通过 / 不通过」与证据位置 |
| V-02 | 检查业务正确性、权限、数据一致性、错误处理、可维护性、敏感信息处理 |
| V-03 | 缺陷闭环：登记 → 开发 Agent 在 `dev/01` 以 `fix` 修复（含编号核验）→ 测试 Agent 复测 → 重新执行受影响轮次 → 验收 Agent 复核 |
| V-04 | 验收后修改业务代码必须重新运行受影响检查；PR 门禁见 `04-workflow-git.md` |
| V-05 | 禁止编造测试结果、接口运行结果、覆盖率数据或部署成功记录 |

## 7. 严格排除

购物车、售后退货、一单多商品、真实第三方支付、真实物流、部分退款、多商户、促销优惠、签收与售后物流、完整财务系统，均不在测试与验收范围内；不得为通过验收而新增题外功能或弱化题面规则。
