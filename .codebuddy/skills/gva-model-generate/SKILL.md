# GVA 模型 & 建表 SQL 生成技能（gva-model-generate）

## Overview

为 `shop-trade` 题目 01 生成 GVA 单体项目下的 GORM 模型与 MySQL(InnoDB) 建表语句。只产出 `model.go` 与 `schema.sql` 两个交付物；保持单商品订单口径，不扩展题面边界。

## 用途

- 在 `dev/01` 上生成业务表对应的 GORM 结构体与建表 SQL。
- 把 `ENGINE=InnoDB`、`utf8mb4`、整数「分」、单商品订单、审计只追加等约束落到模型与 DDL。
- 为开发 Agent 后续在 `server/service/` 编写业务事务代码提供可持久化的数据结构。

## 触发场景

- 用户要求生成 GVA GORM 模型、建表 SQL、`model.go`、`schema.sql`。
- 用户要求初始化题目 01 的商品、订单、库存、收款、退款、发货、异常支付、支付通知处理结果、审计流水等表结构。
- 用户要求核对模型字段与 MySQL(InnoDB) 表结构是否满足题目 01 业务边界。

### 不触发

- 生成 service 业务代码、接口定义、Apipost 用例、单元测试、页面或部署脚本。
- 生成购物车、多商品一单、部分退款、售后退货、真实物流、真实支付渠道或题外功能。
- 修改 GVA 脚手架底层目录，或跨角色改写测试 Agent / 验收 Agent 的交付物。

## 输入

- 原始题面、需求文档 v1.0、原型设计文档 v1.0、任务规划文档 v1.1。
- `.agent/01-stack-structure.md` 至 `.agent/06-workflow-devflow.md`、根目录 `AGENTS.md`。
- 经学生确认的表清单、字段口径、版本号与需求/Bug 编号。
- 既有 GVA 目录约定与 `dev/01` 对应代码版本。

## 执行步骤

1. 读取输入文档与隐藏目录 `.agent/`，核对技术栈、表清单、业务边界、并发与索引要求。
2. 检查是否存在上游文档冲突；发现旧技术栈表述时记录待学生确认项，不自行改写上游文件。
3. 确认当前分支为 `dev/01`；确认交付路径位于项目既有模型目录，不触碰 GVA 脚手架底层目录。
4. 生成 `model.go`：仅包含 GORM 结构体、表名、字段类型、索引与必要标签；金额字段使用 `int64`，状态与标识字段保持可读；不写入业务规则。
5. 生成 `schema.sql`：每张业务表使用 `CREATE TABLE ... ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;`；为主键、渠道交易号、订单状态、商品标识、买家标识、库存更新条件建立必要索引。
6. 校验一单一商品口径：订单表只保存单一商品标识、数量、下单时单价快照与整数分金额；不生成购物车表、订单项明细表、多商品关联表、部分退款表或售后退货表。
7. 校验并发口径：订单行与商品可售数量行的更新条件必须命中索引；渠道交易号唯一；审计流水无更新/删除入口。
8. 输出文件清单与核查结论；需要提交时按 `docs` 类型单独提交 Skill 变更，按对应类型提交 `model.go` 与 `schema.sql`，并在 `feat`/`fix` 前完成 meegle 核验。

## 输出格式

仅生成以下两个交付文件，并在控制台给出路径与核查摘要：

```text
model.go
schema.sql
```

`schema.sql` 的每条 `CREATE TABLE` 必须以如下后缀收尾：

```sql
ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

`model.go` 与 `schema.sql` 不得包含 service 业务代码、接口定义、测试用例、页面或部署配置。

## 失败处理

- 缺少经确认的表清单、字段口径或编号：停止生成，列出缺失项，等待学生确认；禁止脑补。
- 发现购物车、多商品一单、部分退款、售后退货或其他题外需求：明确拒绝并说明依据，不生成对应结构。
- 发现其他数据库方言、非 GVA 技术栈或题外业务域：停止生成并记录违规点。
- 发现上游文档技术栈冲突：保留 MySQL(InnoDB) 口径，记录待学生确认项，不改写上游文档。
- meegle 核验失败或编号不属于相应需求/缺陷：禁止提交。
- 任一质量门禁失败：登记缺陷，交回开发 Agent 在 `dev/01` 修复，重新执行受影响检查后再复核。

## 完成标准

- `model.go` 与 `schema.sql` 已生成在 `dev/01` 的约定路径。
- 全部业务表显式使用 `ENGINE=InnoDB` 与 `utf8mb4`。
- 金额全部为整数「分」，无浮点字段。
- 单商品订单口径成立；无购物车、多商品、部分退款、售后退货结构。
- 渠道交易号唯一索引、订单/商品行锁索引、审计只追加约束均已落到 DDL。
- 未修改 GVA 脚手架底层目录，未跨 Agent 修改测试或验收文件。
- 输出中文、证据真实、敏感信息已脱敏；`skill-usage.md` 已登记本次实际调用。
- 本 Skill 产物可进入后续三轮验证，不能仅凭 AI 自述判定通过。

## 常见错误

| 错误 | 修正 |
| --- | --- |
| 漏写 `ENGINE=InnoDB` 或 `utf8mb4` | 每条 `CREATE TABLE` 补齐后缀并复核 |
| 用浮点类型保存金额 | 改为整数「分」与 `BIGINT` / `int64` |
| 生成订单项明细表或多商品关联表 | 删除并恢复单商品单订单行口径 |
| 更新条件未命中索引 | 补充索引，避免行锁升级为表锁 |
| 把业务规则写进模型文件 | 移到 `server/service/`，模型只保留结构声明 |
| 依据历史旧技术栈生成其他数据库产物 | 以 `.agent/` 的 MySQL(InnoDB) 为准并记录冲突 |
| 跳过 meegle 核验直接提交 `feat`/`fix` | 执行核验并保留输出，失败则禁止提交 |
