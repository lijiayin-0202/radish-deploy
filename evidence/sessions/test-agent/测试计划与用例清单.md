> 被测版本：`dev/01` @ `bb1ca7fbce37ed22c83c29af484f79239ee32690`
> 执行方式：纯黑盒 HTTP（`http://127.0.0.1:18099`，demo-memory 模式，不连接 MySQL）
> 执行脚本：`evidence/sessions/test-agent/黑盒探测脚本.py`（本 Agent 自写）

## 0. 测试策略与总体设计

| 项 | 设计 |
| --- | --- |
| 测试层次 | ① Go 质量门禁（gofmt / vet / build / test / 覆盖率 / race）；② HTTP 黑盒业务探测（本 Agent 自写脚本） |
| 隔离性 | 黑盒脚本自行 `go build` 并启动被测进程（`GVA_ADDR=:18099`，**不设 `GVA_MYSQL_DSN`**），跑完自行停止并清理；不读取被测包内部状态，只看 HTTP 响应 |
| 判定依据 | 需求文档 R-xx / T-xx / F-xx / E-xx / AC-xx；原型文档 3.3 M-xx 文案表；AGENTS.md Q-02/Q-03/Q-04 |
| 断言强度 | 每条用例都是**可证伪断言**（具体数值 / 错误码 / 文案逐字比对）；不做“只看返回 200”式弱断言 |
| 并发构造 | 20 并发抢单：20 个真实 Python 线程同时发起下单（数量交替 1/2）；退款与发货并发：2 轮，每轮 2 个线程同时发起 |
| 超时构造 | 通过 `POST /api/v1/admin/clock` 把**服务端时间**整体前移 11 分钟（A-01 允许的教学时钟，仅平移时间，不改 10 分钟规则），再触发 `close-expired` |
| 库存预算 | demo-memory 预置 goods1=5 件、goods2=2 件且**无可售数量维护接口**，故按峰值同时占用 ≤7 编排 |
| 缺陷处理 | 只登记、不修复；不改生产代码、不改既有断言、不弱化断言 |
