## 4. 与既有 `evidence/` 下历史报告的区别

本 Agent 在开始前**通读了 `evidence/` 目录结构与文件名清单**，确认历史产物包含：
`test-report.md`、`coverage-report.md`、`gofmt-vet-output.txt`、`race-output.txt`、`race_raw_output.txt`、
`demo-five-scenarios-output.txt`、`error_code_enumeration.{py,json,txt}`、`api_validation_probe.py`、
`mysql_*` 系列（含 `mysql_verify.sh`、`mysql_raw_0*.txt`）、`wsl_race_run.sh`、`manual/`、`manual-round2/`、
`smoke/`、`partial-closure/` 等。

**本 Agent 与它们的实质区别：**

| 维度 | 既有历史报告 | 本 Agent 的独立测试 |
| --- | --- | --- |
| 上下文 | 开发 / 既有测试会话 | **全新独立会话**，不继承任何历史结论 |
| 用例来源 | 既有脚本（`api_validation_probe.py`、`error_code_enumeration.py` 等） | **本 Agent 自写**的 `黑盒探测脚本.py`（仅用 Python 标准库，147 条断言，编号 TC-*） |
| 断言基准 | 未逐条对照原型 3.3 | **逐字比对**原型设计文档 3.3 的 M-01~M-30 文案表，并区分「顶层业务拒绝码」与「事件记录 `failure_code`」两类 |
| 五组场景 | 既有 `demo-five-scenarios-output.txt` 等 | **本 Agent 独立跑通 S1~S5**，并用**真实线程并发**验证 20 并发抢单与退款/发货并发裁决 |
| 权限隔离 | 既有证据 | **本 Agent 独立覆盖 5 个角色 × 允许/拒绝矩阵 29 条**，并验证改 `X-User-Id`/`X-Role` 不能越权 |

| 持久化结论 | 历史含 MySQL 证据 | **本 Agent 无 MySQL 实例，明确标注 E-15 重启一致性为阻塞**，不以 demo-memory 模式的内存态冒充持久化证据 |
