## 3. 分场景结论

### 3.1 场景 S1「活动正常成交」—— 通过（12/12）

实测链路：运营查商品 → buyer01 下单 2 件（应付 20000 分）→ 库存预扣（可售 3 / 占用 2）→ 模拟渠道支付成功通知 → 转待发货 → 仓库登记发货（`SF`/`SF0001`）→ 转已发货 → 买家查到运单 → 运营汇总已收款 20000 分、已发货 1 单 → 运营调价 12000 分 → 既有订单单价/金额快照不变 → 调价复原。

对应验收项：AC-02 通过（已收款 20000 分、可售 3 件、发货 1 条）；AC-03 通过（快照不变）。**AC-02 的「已退款 0 分」无法在汇总中直接读到**（见 D-01）。

### 3.2 场景 S2「缺货与弃单」—— 通过（18/18）

- **20 并发抢单**：20 个真实线程同时下单（数量交替 1/2），实测成功 3~4 单、**预扣合计 5 件 = 可售上限，绝不超卖**；可售 + 占用 = 5；被拒 16~17 单**全部返回 M-02** 并给出中文原因；成功 + 被拒 = 20，被拒不产生订单；占用数恰等于成功订单数量之和（无孤立占用）。
- **可售不足被拒**：可售为 0 时，下单 1 件与 2 件均返回 `M-02` 且库存不变。
- **释放**：逐单取消，预扣合计一次性全部释放，回到可售 5 / 占用 0；重复取消同一订单返回 `M-10` 且库存**不再释放**。
- **释放后可再购买**：其他买家再次下单成功（AC-15）。
- **10 分钟超时关闭**：演示时钟前移 11 分钟 → `close-expired` → 订单转已关闭、预扣释放一次、`closed_count=1`；再次关单 `closed_count=0`、库存不多释放；对已关闭订单再主动取消返回 `M-10`（主动取消与超时关闭只生效一次）。时钟复位为 0。

对应验收项：AC-05、AC-09、AC-15 通过。

### 3.3 场景 S3「售前退款」—— 通过（15/15）

链路：买家申请整单退款 → 转退款审核中（发货暂停）→ **仓库登记发货被拒，订单状态不变** → 客服同意并写明原因 → 转退款处理中 → 渠道明确退款失败 → 返回 `M-08`、保留待处理、订单**不回到可发货** → 客服重试（`refund_retry_count=1`）→ 渠道再次通知成功 → 转已退款 → **库存恢复一次（+2），回到退款前水位** → 重复退款成功通知**不重复退款、不重复恢复库存** → 买家可见退款状态「成功」与 20000 分 → 运营逐单核查 `actual_restore_times=1 / expected=1 / consistent=true` → 已退款订单再发货返回 `M-11`、再申请退款被拒。

**一处需注意但不计为失败**：申请期间仓库发货的实际错误码是 **M-22**（文案「退款与发货并发：本单已进入退款流程，发货未登记；仅形成一种合法业务结果」），而原型 3.3 规定「申请期间仓库尝试发货」对应 **M-07**。业务行为正确（发货被拒、状态不变），仅错误码编号与原型不一致，且 M-07 成为永不可达的死码。已登记为 **D-03（产品缺陷，轻微）**，未计入失败用例（TC-S3-04 的断言为「被拒 + 状态不变」，成立）。

对应验收项：AC-11、AC-12 通过。

### 3.4 场景 S4「迟到支付」—— 通过（15/15）

链路：待支付订单 → 服务端时间满 10 分钟关闭、预扣释放一次 → 关闭后收到支付成功通知 → 返回 `M-09` 且响应携带 `data.event_id`（异常支付待处理记录）→ **订单保持已关闭终态、库存未重新占用** → 再次关单 `closed_count=0`、库存不多释放 → 客服核实并记录原因（异常支付已核实）→ 重复核实返回 `M-10` → 发起迟到支付退款（`failure_code=M-26`）→ 重复发起返回 `M-10` → 渠道迟到退款成功回调 → **可售数量不二次增加（关键断言通过）**、订单仍已关闭 → 运营逐单核查 `actual=0 / expected=0 / consistent=true` → 汇总中 `late_payment_events≥1`、`late_payment_refunded_events≥1`。

对应验收项：AC-10 通过。

### 3.5 场景 S5「操作竞争」—— 通过（14/14）

- **退款与发货并发**（2 轮，每轮 2 个真实线程同时发起）：**从未出现「两者都成功」的非法双重结果**；后到者一律被明确拒绝并给出 M-xx 原因；最终订单状态唯一且合法。
- **重复支付通知**：同一订单连续 3 次内容相同的成功通知，第 1 次「已记款」，第 2/3 次「重复支付通知已幂等处理，未重复记款」；已收款合计**不变**；库存占用不重复变化；订单仅一次进入待发货。
- **重复退款通知**：结果为「重复退款通知已幂等处理，未重复退款」，库存未二次恢复。
- **同一渠道交易号指向第二单**：第 2 单返回 `M-27`「同一渠道交易号已归属其他订单，本次关联被拒」，该单状态保持待支付。
- **越权**：见 3.7。

对应验收项：AC-13、AC-08、AC-06 通过。

### 3.6 边界与异常 —— 26 通过 / 1 失败 / 1 阻塞

通过项包括：数量 0 / 3 / -1 → `M-03` 且不创建订单、不预扣库存；`goods_id=0` → `M-04`；不存在的商品 → `M-01`；未支付订单发货 → `M-18`；承运方/运单号为空 → `M-23`；审核不写原因 → `M-24`（同意与拒绝均验证）；客服拒绝并写明原因 → 回待发货 → 允许继续发货；重复发货 → `M-19` 且运单号不变；已发货申请退款 → `M-11`；待支付申请退款 → `M-05`；未知订单 → `M-30`；未知异常事件核实 / 发起退款 → `M-14`；超时后取消 → `M-06`；渠道超时通知只登记不改状态、重复通知幂等；金额为整数分且 `total = unit_price × quantity`；已取消订单收到通知 → `M-15` 且订单不变；金额不符 → `M-29`、验签失败 → `M-28`、未知订单通知 → `M-30`，三者订单状态均不变且响应携带 `event_type=支付通知处理结果` 的处理结果。

### D-01（重要｜产品缺陷）运营核查汇总缺少「已退款合计（分）」

| 项 | 内容 |
