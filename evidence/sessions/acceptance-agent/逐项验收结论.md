## 〇、判定口径（先声明，避免歧义）

1. **通过**＝在该提交对应的代码与真实证据上，该验收项的判定标准全部成立，且可定位到具体文件行号或证据文件。
2. **不通过**＝存在明确不符：标准中的某一项不成立，或在当前交付基线上**不可实际触发 / 不可实际查询**。凡属此类均写明「差在哪一行 / 差在哪个文件」。
3. **无法判定**＝受环境限制（本机无 MySQL、无 C 编译器、无远端 GitHub、禁用 WSL）或证据本身缺失，无法给出有依据的通过/不通过结论；此类**不判为代码缺陷**，并注明原因。
4. **AC 项**严格按需求文档第 9 章「通过标准」原文逐字判定；原型页面按原型文档第 2 章「页面组件 / 展示字段 / 按钮操作 / 状态分支展示」四要素判定。
5. 同一缺陷在多处体现时各项分别如实判定（不因「已在别处扣分」而放过），并在「说明」列互相指引。
