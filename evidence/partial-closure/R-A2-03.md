## 2. 缺口说明（本轮为何仍不能升级为 `pass`）

- 20 并发下单在本轮**实测通过**：请求总数守恒（成功 + 库存不足 = 20），且并发后商品可售 / 占用守恒。但 `demo-memory` 仓储用互斥锁串行化，**不等于**真实 InnoDB 行锁下的并发语义。
- `go test -race` 本轮无法执行：`go env CGO_ENABLED` = 0，本机 `where gcc` / `where clang` 无结果，`-race requires cgo`（详见 `R-A3-03` 条目，该条维持 `unknown`）。
- 真实 InnoDB 行锁（`SELECT ... FOR UPDATE`）下的并发扣减与超卖防护，本轮**没有任何实测运行结果**。

## 3. 解除条件（可核查、可执行）

- 安装 gcc 或 clang，并设置 `CGO_ENABLED=1`，执行 `go test -race ./server/...` 保存完整原始输出，确认无 `WARNING: DATA RACE`。
- 在真实 MySQL 实例上以 `GVA_MYSQL_DSN` 启动服务，重跑 20 并发下单（同一脚本、同一订单商品），保存并发后的 `SELECT available_stock, occupied_stock FROM goods WHERE id=1` 结果，验证不超卖且守恒。
- 两者原始输出 + 真实 MySQL 版本号 + 提交哈希齐备后，本条可升为 `pass`。
