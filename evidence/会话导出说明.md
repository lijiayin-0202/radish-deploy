| --- | --- |

## 1. 强制要求

- 开发、测试、验收可使用同一工具与模型，但**必须使用相互独立的会话或任务上下文**，会话记录分别导出。
- 测试 Agent 与验收 Agent 必须读取**原始题面与对应版本代码**，不得仅根据开发 Agent 的「已完成 / 已通过」声明判断结果。
- 三个角色不得互相代写对方交付物、不得进入对方会话修改其文件；**AI 自述「通过」不作为验收依据**。
- 学生是唯一可跨会话协调、确认边界变更与发起合并的人。
- 每次会话须记录：阶段、任务编号、模型、关联代码版本（提交哈希）、输入与输出位置（S-05）。

## 4. 后续补齐方式（不得事后补造）

1. 由学生新建**独立**测试 Agent 会话，提供原题、文档、`git rev-parse HEAD` 对应版本与运行说明，执行第 1、2 轮并保存原始输出；导出该会话。
2. 由学生新建**独立**验收 Agent 会话，提供全部证据，执行第 3 轮与 `ACC-01~05`；导出该会话。
3. 将本开发会话按平台支持的导出功能另存为 Markdown；平台不提供的字段标注「不可获取」，**不索取隐藏推理、不臆造消息**。
4. 历史消息缺页、时间不可还原的部分必须如实标注缺失范围；**禁止完工后补写会话冒充当日独立会话**（`AGENTS.md` P-05、`AGENTS.md` 7 章版本规则）。
5. 导出前按 `AGENTS.md` P-03 与 `evidence/交付证据说明.md` 第 7 节完成脱敏。
