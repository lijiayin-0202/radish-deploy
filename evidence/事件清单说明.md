# 结构化事件清单说明（JSON / JSONL）

| 项 | 内容 |
| --- | --- |
| 文件性质 | 开发 Agent 编写的**字段规范与生成方式说明**；**不是事件清单本体** |
| 依据 | 任务规划文档 `DOC-03`、题面共同要求第 8/9 节、`AGENTS.md` 2.5/6、`outputs/单题检查/.../检查报告.md` B2/E-021 |
| 目标文件（尚不存在） | `evidence/events.jsonl`（按时间升序，一行一个事件） |
| 当前状态 | **未生成正式清单** |

## 1. 为什么没有直接生成清单

`DOC-03` 要求「按时间排序的结构化事件清单，覆盖需求分析到上线验收全部阶段，含学生输入、AI 回复、Agent 指令与 Skill 版本及使用记录、工具调用与失败重试」。

本轮上下文多次被压缩为结构化总结，**无法还原每轮消息、工具调用的精确时间戳与原始输入输出**。若此时凭总结编写 `events.jsonl`，等于编造过程事件，违反 `AGENTS.md` P-01 与 `.agent/06` P-02。因此只提供规范与缺口登记，正式清单须由学生在可导出完整会话的环境生成。

## 2. 事件字段规范（每行一个 JSON 对象）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `seq` | int | 递增序号，按真实发生顺序 |
| `ts` | string | 平台可导出的真实时间（ISO 8601 + 时区）；不可获取时写 `"unavailable"`，**不得估算或编造** |
| `stage` | string | 需求分析 / 原型设计 / 任务规划 / Agent 开发 / Agent 测试 / Agent 验收 / 自动部署上线 |
| `task_id` | string | 如 `DB-01`、`BE-01`、`TST-S1`、`ACC-03`、`DOC-03` |
| `agent_role` | string | `dev` / `test` / `accept` / `student` / `ci` |
| `session_id` | string | 对应会话导出文件，用于证明三 Agent 隔离 |
| `actor` | string | `student` / `ai` / `tool` / `pipeline` |
| `action` | string | `prompt` / `reply` / `tool_call` / `tool_result` / `retry` / `confirm` / `commit` / `verify` / `defect` / `retest` |
| `skill` | string \| null | 实际调用的 Skill 名称与版本；未调用记 `null` |
| `input_ref` / `output_ref` | string \| null | 输入文档、代码文件、产物路径 |
| `result` | string | 真实结果（含失败与重试原因）；不得写「通过」掩盖失败 |
| `evidence_ref` | string \| null | 原始输出、截图、报告、提交哈希位置 |
| `commit_hash` | string \| null | 该事件对应的代码版本 |
| `notes` | string | 缺失范围、脱敏说明、学生确认记录（C-xx） |

## 3. 必须覆盖的阶段与事件类型

1. 学生输入与边界确认：四项前置授权、`C-01~C-08` 相关确认。
2. AI 回复与 Agent 指令：需求/原型/规划/`AGENTS.md`/`.agent/`/Skill 的生成与校验。
3. Skill 版本与调用：`skill-usage.md` 第 5 节列出的真实调用，含「发现问题 → 修正 → 复检」。
4. 工具调用与失败重试：编码问题、PowerShell 中文乱码、`event_id` 缺失、`go vet` 失败、race 因 CGO 未启动等真实失败（`test-report.md` D-01~D-06）。
5. 开发产物与提交：`schema.sql`、源码、`dev/01` 首次提交哈希。
6. 测试与验收：命令原始输出、覆盖率、缺陷登记与复测、逐项结论。
7. CI / 部署 / 视频 / 群提交：如发生，须含版本对应与冒烟结果。

## 4. 生成与校验方式

```powershell
# 由学生在可导出会话的环境生成后校验（本轮不执行，不生成伪数据）
Get-Content evidence/events.jsonl | ForEach-Object { $_ | ConvertFrom-Json } | Out-Null
# 校验：seq 递增、ts 升序、"unavailable" 项已标注缺失、commit_hash 与 git log 对应、
#       session_id 可追到三份独立会话导出、敏感字段已脱敏
```

校验结果须保留原始输出；`ts` 为 `"unavailable"` 的记录必须在报告中说明缺失范围，不得据此声称「全过程可追溯已通过」。

## 5. 脱敏要求

密钥、访问令牌、演示口令、签名密钥及用户手机号、身份证、邮箱、地址等敏感信息一律脱敏后再写入清单；平台不提供的字段标注「不可获取」，不索取隐藏推理。
